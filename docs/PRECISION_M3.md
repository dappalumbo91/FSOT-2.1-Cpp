## Fixes in corrected mode (`include/fsot/host/ledger_b.hpp::analyze_benchmark`, recompute branch)
None of these rules changes a computed value. Each one only decides which error the gate reads.

1. **`zero_target`:** `measured == 0` keeps the stored error. Counted in `zero_target_rows_kept_stored` and `stored_only`.
2. **`bound`:** if the record's `formula` contains `≤` or `<=`, the error is 0 when m ≤ c, otherwise the relative excess.
3. **`contraction`:** rows with `residual_after` and `initial_offset` score 0 if the residual contracted, otherwise 100.
4. **`computed_rounded`:** applies when all of these hold:
   - `computed` has d = max(repr decimals, 6) decimals.
   - \|c − m\| ≤ 0.5·10⁻ᵈ. For Ledger B emitter rows, the alternative \|c − m(1+e/100)\| ≤ 0.5·10⁻ᵈ is also accepted.
   - The recomputed error exceeds the gate.

   Such a row is treated as not recomputable and keeps its stored value. (The max(…, 6) clause covers
   `round(x, 6)` values that print with fewer decimals, e.g. 6e-05.)
5. **Gate tolerance:** the gate limit is 0.5 %·(1 + 1e−12) in corrected mode only, so an exact 0.5 % isn't failed by float noise.

## Needs a theory or data decision (Damian)
1. Should rows with a reference uncertainty be gated at that uncertainty instead of 0.5 %? All 7 formula misses are inside their bands.
2. FRB periodicity: one prediction (1000 s) is scored against 3 FRBs with different periods.
3. Target-derived rows are labelled genuine: `literature_anchor` founding panels (c = m(1+\|S\|·0.0005)), planetary Europa/Io (fsot_val from the observation) and PRED-004 (measured = fsot_predicted). Should they be STRUCTURAL?
4. Relay spines (`circuit_component_emergence_lib.py:432-436`) relabel Ledger B rows as `live_formula`.
5. Emitters store `computed` rounded (6 decimals or 10). Storing `round_sig(c, 12)` would make every row recomputable. Until then, C++ falls back to the stored error for 6,198 rows.
6. Stale stored `error_pct` values in hub data: 50,436 rows disagree with their own fields, including all 7 formula misses.
7. The two Cepheid/SH0ES `host_mu_vs_trgb_mean` rows are labelled `fsot_prediction`, but their computed value is not a Ledger B correction.
